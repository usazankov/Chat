# Chat

Учебный клиент-серверный чат на Qt/C++ (C++11). Связь клиента с сервером — по TCP-сокетам
(QTcpSocket/QTcpServer), обмен — собственным протоколом на основе JSON.
Разработка: апрель — декабрь 2018 года.

## Возможности

- Авторизация на сервере по имени пользователя (поле `User_id`, без пароля);
- Отправка сообщений: сервер рассылает сообщение всем подключённым клиентам;
- Список пользователей и статусы онлайн/офлайн (`u_online` / `u_offline`);
- Оповещение клиентов о подключении и отключении других пользователей;
- Автоматическое переподключение к серверу (таймер 5 с) и повторная авторизация;
- Очередь команд на клиенте: команды накапливаются до соединения и авторизации;
- Многопоточная обработка запросов на сервере (QtConcurrent, глобальный пул потоков);
- Ограничение частоты запросов на сервере (RequestFilter: ответ `timeout_limit_exceeded`,
  при превышении — разрыв соединения).

## Протокол

Транспорт — TCP. Блок данных: 4 байта размера + JSON-объект (чтение/запись через QDataStream).
Константы протокола собраны в `Common/common_consts.h`:

- команды клиента (`Command_obj` → `Command_id`): `c_auth_req` — авторизация,
  `c_check_connect` — проверка соединения, `c_get_users` — список всех пользователей,
  `c_send_message` — отправка сообщения (также объявлены `c_get_count_online`,
  `c_get_online_users`, `c_get_user_info`, `c_get_events_users`);
- события сервера (`Event_obj` → `Event_id`): `e_connect_user`, `e_disconnect_user`,
  `e_message`, `e_users_list`;
- ответы: поле `Code_resp` (`c_success` / `c_error`), объект `Error_obj` с кодами ошибок
  (`Error_parse`, `Error_missing_user_id`, `Error_empty_message`, `Error_name_invalid`,
  `Error_name_is_use`), идентификатор запроса `id_msg`.

Сервер (`TestServer/parserclientjson.cpp`) обрабатывает команды: авторизация, отправка
сообщения, запрос списка пользователей, проверка соединения. Ответы формируются цепочкой
обработчиков-декораторов (время, идентификатор команды, идентификатор сообщения, код ошибки).

## Технологии

- Qt 5: модули QtNetwork, QtConcurrent (сервер), QtQuick / Qt Quick Controls 2 (GUI);
  конкретная версия Qt в .pro-файлах не указана (QML-импорты — QtQuick 2.2, Controls 2.2);
- C++11 (`CONFIG += c++11`), сборочная система — qmake.

## Структура проектов

Корневой `Chat.pro` (TEMPLATE = subdirs) собирает подпроекты LibChat, TestApp, TestServer, ChatApp:

- **LibChat** — клиентская библиотека (TEMPLATE = lib): фасад-синглтон `LibChat`, `ChatClient`,
  сетевой уровень `ChatTCPManager` (QTcpSocket), менеджер команд, команды (паттерн «Команда»),
  парсер ответов, модели пользователей и сообщений на QAbstractListModel для QML;
- **Common** — общие исходники без собственного .pro, компилируются в составе LibChat:
  `ChatRequest` (построение JSON и сериализация в блок), константы протокола, экспортные макросы;
- **ChatApp** — графический клиент на QML: окно со списком пользователей и полем ввода
  сообщения; при старте автоматически подключается к серверу и отправляет тестовое сообщение;
- **TestApp** — консольный тестовый клиент на LibChat: подключается к серверу (адрес задан
  в коде, порт 1977) под сгенерированным именем и отправляет сообщение;
- **TestServer** — сервер чата: QTcpServer (порт 1977), обработка запросов в пуле потоков,
  хранилище пользователей `GlobalStorage`, рассылка событий;
- **Server** — ранний прототип многопоточного сервера, в SUBDIRS не входит (из сборки исключён).

## Тесты

- **TestApp** — проверка клиентской библиотеки «вживую»: соединение, авторизация,
  отправка сообщения;
- **TestServer** — фактически основной сервер проекта (несмотря на имя): ведёт отладочный
  вывод принятых запросов и ответов в консоль; при сборке с define `TEST` добавляет
  тестовых пользователей user1–user3.

## Сборка

qmake + make по корневому `Chat.pro` (Qt 5, C++11). LibChat и консольные приложения
складываются в каталог `Out/`. Сервер слушает порт 1977.

## Статус

Учебный/экспериментальный проект 2018 года, не завершён: графический клиент — тестовый,
комнаты и история сообщений не реализованы, приём сообщений в модель на клиенте не доведён.
